Hardware SelectionChoose your platform — new build, repurposed PC, or NAS device
▾
Option Cost Performance Power Use Best For
Old PC / Desktop $0–$50 High 80–150W Getting started fast
Mini PC (N100/N305) $150–$300 Medium 10–20W Low power, always-on
Dedicated NAS (Synology) $300–$700+ Medium 15–30W Ease of use, reliability
Custom ITX Build $400–$800 Very High 40–80W Max expandability
Tip: For hardware transcoding (H.264/HEVC without CPU burn), look for Intel Quick Sync via an Intel N-series or Core CPU with iGPU. This drastically reduces power draw during streaming.
  • RAM
    Memory: 8GB minimum, 16GB recommended

    If running Docker containers for the full *arr stack + media server, 16GB is comfortable. ECC RAM is ideal but not required for home use.

  • CPU
    Processor: Intel N100 / N305 or Ryzen 5xxx series

    Intel N-series offer excellent iGPU transcoding at very low wattage. Avoid AMD for transcoding unless using a dedicated GPU.

  • HDD
    Storage: 2+ HDDs for redundancy

    NAS-rated drives (WD Red, Seagate IronWolf) are rated for 24/7 operation. Start with 2×4TB and expand. Use an SSD for the OS.

Operating System SetupInstall and harden your server OS
▾

Choose your OS based on your comfort level and goals:

Ubuntu Server 24.04 LTS ⭐
Debian 12
TrueNAS Scale
Unraid
OpenMediaVault
Proxmox VE
Recommendation: Ubuntu Server 24.04 LTS for flexibility + Docker support. TrueNAS Scale if you want a polished GUI and ZFS out of the box. Unraid if you want mixed drive sizes without RAID.
  • 3.1
    Flash OS to USB and boot

    Use Balena Etcher or Rufus to write the ISO. Boot from USB, follow install wizard. Choose "minimized install" for servers — no GUI bloat.

  • 3.2
    Set a static IP address

    Edit /etc/netplan/ or use your router's DHCP reservation to assign a permanent local IP (e.g., 192.168.1.100).

  • 3.3
    Enable SSH and harden access

    Disable root login, use SSH key auth instead of passwords. Install fail2ban to block brute force attempts.

  • 3.4
    Install Docker & Docker Compose

    Almost all modern home server apps run in Docker. Use the official Docker install script for your distro.

# Install Docker on Ubuntu curl -fsSL https://get.docker.com | sh sudo usermod -aG docker $USER # Verify installation docker --version && docker compose version
04
Storage ConfigurationFormat drives, set up RAID or ZFS, configure shares
▾
RAID TypeMin DrivesRedundancyUse Case
RAID 1 (Mirror) 2 1 drive failure Simple home setup, easy
RAID 5 3 1 drive failure Balanced storage + parity
ZFS RAIDZ1 3 1 drive failure Best integrity, checksumming
No RAID (JBOD) 1+ None Max capacity, backup elsewhere
  • 4.1
    Identify your drives

    Run lsblk and smartctl -a /dev/sdX to confirm drive health before using them.

  • 4.2
    Create ZFS pool (recommended)

    ZFS offers checksumming, snapshots, and self-healing. Use zpool create to set up mirrors or raidz.

  • 4.3
    Mount and set permissions

    Mount your pool to /mnt/storage. Create subdirectories: /media, /downloads, /backups. Set ownership to your docker user.

  • 4.4
    Set up network shares (Samba)

    Install Samba for Windows/Mac file sharing. Configure /etc/samba/smb.conf with your share paths and user credentials.

Important: RAID is NOT a backup. Always maintain a separate backup of irreplaceable data per the 3-2-1 rule: 3 copies, 2 media types, 1 offsite.

06
Remote Access & SecurityAccess your server safely from anywhere
▾
  • 6.1
    Reverse Proxy with Nginx Proxy Manager

    Route subdomains (jellyfin.yourdomain.com) to local container ports with auto SSL via Let's Encrypt. No port forwarding headaches.

  • 6.2
    VPN Tunnel with Tailscale or WireGuard

    Tailscale is zero-config and free for personal use — installs in minutes and gives you a private mesh network to your server from any device.

  • 6.3
    Cloudflare Tunnel (Cloudflared)

    Expose services publicly without opening any ports on your router. Free, secure, and works behind CGNAT. Ideal for Jellyfin remote access.

  • 6.4
    Firewall with UFW

    Enable UFW, deny all incoming by default, and only allow SSH (22), your VPN, and any intentionally exposed ports.

Never expose Sonarr, Radarr, or download clients directly to the internet. Keep these behind your VPN or LAN-only.
07
Monitoring & MaintenanceKeep your server healthy long-term
▾

Track these regularly to prevent data loss and downtime:

  • Monitor drive health weekly with smartmontools
  • Run ZFS scrub monthly to detect silent corruption
  • Set up Uptime Kuma for container/service monitoring alerts
  • Configure email/Telegram alerts from Sonarr/Radarr on failures
  • Automate OS updates with unattended-upgrades
  • Verify backup integrity with test restores quarterly
  • Keep a spare drive on hand for fast replacement
Recommended monitoring stack: Uptime Kuma (service health) + Grafana + Prometheus (metrics) + Ntfy.sh or Gotify (push notifications). All run as Docker containers.
